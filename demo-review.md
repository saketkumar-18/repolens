### src/taskman/search.py:11

🔴 **Critical** · `correctness` · _llm_

`sqlite3.connect(":memory:")` opens a brand-new empty in-memory database on every call. The `tasks` table is never created, and the existing TaskStore is in-memory Python dicts — not SQLite — so this query will always raise `OperationalError: no such table: tasks`. The function is non-functional as written.

**Suggested change:**
```suggestion
Either query the real TaskStore (e.g. add a `search_by_owner(self, owner, query)` method to TaskStore that filters `self._tasks` in Python), or, if SQLite is intended as a separate search index, open a persistent connection, create the schema, and populate it from the store.
```

### src/taskman/store.py:22

🔴 **Critical** · `correctness` · _llm_

`return copy.deepcopy(task) if task else None` breaks `TaskService.complete_task` in `src/taskman/service.py`, which does `task = self.store.get(task_id)` and then `task["done"] = True`. After this change, that mutation lands on a throwaway deep copy and is never persisted back to `self._tasks`, so `complete_task` becomes a silent no-op. The existing test `test_create_and_complete` will pass only because it never re-reads the task; any real re-read will show `done == False`.

**Suggested change:**
```suggestion
Keep `get` returning a defensive copy (a shallow copy is sufficient since values are immutable strings/bools), and change `complete_task` to use a store-level mutation, e.g. add `TaskStore.mark_done(task_id)` and call it from the service. Alternatively, have `complete_task` do `self.store.set(task_id, {...task, "done": True})`.
```

Related: `src/taskman/service.py`

### src/taskman/api.py:24

🟠 **Warning** · `general` · _llm_

`handle_search` blindly indexes `request["q"]` and `request["owner"]` with no validation. Compared to the existing `handle_create` flow which goes through `TaskService.create_task` (which validates non-empty title), this bypasses any service-layer input checks and forwards raw strings into a SQL query.

**Suggested change:**
```suggestion
Add a `TaskService.search_tasks(owner, query)` that validates `owner` is non-empty and normalizes the query, then call that from `handle_search` instead of `search_tasks` directly. Also handle missing keys with a clear 400-style error instead of `KeyError`.
```

Related: `src/taskman/service.py`, `src/taskman/search.py`

### src/taskman/search.py:16

🟠 **Warning** · `correctness` · _llm_

`[dict(r) for r in results]` constructs dicts from sqlite Row tuples, but the keys will be positional (0, 1, 2, …) rather than the actual column names, because the cursor was not created with `row_factory = sqlite3.Row`. The returned "dicts" are also not JSON-serializable-friendly in a stable shape. Even if the table existed, the return type would be misleading.

**Suggested change:**
```suggestion
Set `conn.row_factory = sqlite3.Row` after connecting, then `return [dict(r) for r in cur.fetchall()]`. Or return a list of typed dataclasses matching the Task shape used elsewhere.
```
